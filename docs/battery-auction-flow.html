7 — §25's infrastructure list, against what the app already runs

Already there — wire it, don't build it

  • Background workers — BullMQ + Upstash Redis already run the call worker; the auction scheduler is another repeatable job on the same worker process.
  • Audit logs — nbfc_audit_log plus nbfc_auction_lot_actions already record every admin action with before/after.
  • Image storage — S3 is live behind STORAGE_BACKEND, served through the existing file proxy.
  • Payments — Razorpay is already integrated for onboarding fees.
  • RBAC — role middleware and the permissions catalogue cover NBFC and admin; dealer auction permissions are additions to it.
  • Dual approval + MFA — the lot-cancellation ledger already implements it.

Genuinely new

  • Auction scheduler — flips lots live and closed on time, and settles ties by earliest bid.
  • Anti-snipe — a bid in the last N seconds extends the deadline. Without it a 2-hour auction is decided in its final second.
  • Live bid updates — poll every few seconds first. WebSockets only if the polling load actually shows up; do not start there.
  • Notification fan-out — one publish event, four channels, all queued.
  • Visibility resolver — the only new business rule of any weight.
  • Public auction page — the first genuinely unauthenticated surface in this app; keep it read-only and keep bidder data out of its payload.

8 — Defects already in the existing engine fix these while passing through

None of these are caused by this BRD; they are sitting in the shipped §6.1.7 code and every one of them is on the path of the work above. Clearing them is cheaper now than after a dealer is bidding real money.

DefectWhereEffect, and the fix
Core tables have no migration filedrizzle/ — only E-129 seed existsThe auction and recovery tables live in schema.ts and in whichever database happened to get a db:push. Against the repo's own rule this is the highest-risk item: write the catch-up idempotent CREATE TABLE IF NOT EXISTS migration before adding anything.
No auction close jobno cron, no workerA lot past ends_at stays live forever unless an admin ends it. With a 2-hour auction this is fatal. A BullMQ repeatable job closes lots and picks the top bid.
Auto-bid never executeslots/[id]/auto-bidThe standing maximum is stored and shown to the bidder, and nothing ever acts on it. Either build the proxy engine or stop showing the control.
Paused and cancelled lots vanishauction/service.ts listLots()The list API accepts only live and ended, so a paused lot disappears from every screen rather than showing as paused. Widen the filter.
No way to un-pauseauctionControlService.tsPause exists; resume does not. A paused lot is stuck until cancelled.
Settlement seller is a placeholderapprove_winning_bidThe settlement is created with a zero-UUID seller_tenant_id, so seller-scoped settlement reads can never match. Fixed for free by E-227's seller_tenant_id on the lot.
